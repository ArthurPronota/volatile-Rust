# `volatile` в Rust

## 🧩 Что это

**Volatile-операции** — это чтение и запись памяти, которые компилятор **не имеет права оптимизировать, переупорядочивать, дублировать или удалять**. В Rust это две функции из `std::ptr`:

```rust
pub unsafe fn read_volatile<T>(src: *const T) -> T
pub unsafe fn write_volatile<T>(dst: *mut T, val: T)
```

Обе — `unsafe`, потому что работают с **сырыми указателями** и не проверяют валидность адреса.

## 🎯 Гарантии

Volatile-операции дают три гарантии:

| Гарантия | Что означает |
|----------|--------------|
| **Не оптимизируется** | Компилятор не удалит операцию, даже если результат не используется |
| **Не переупорядочивается** | Порядок между volatile-операциями сохраняется |
| **Не дублируется** | Операция выполняется ровно один раз |

Это критично, когда **чтение или запись имеют побочный эффект** — например, обращение к регистру устройства.

## ⚠️ Чего `volatile` НЕ делает

Это самое важное для понимания:

| Миф | Реальность |
|-----|-----------|
| «volatile делает операции атомарными» | **Нет.** Гонка между `read_volatile` и записью — undefined behavior |
| «volatile синхронизирует потоки» | **Нет.** Для многопоточности — `Atomic*` |
| «volatile гарантирует видимость в других потоках» | **Нет.** Нет memory barriers, нет ordering |
| «volatile работает как `Mutex`» | **Нет.** Это не примитив синхронизации |

`read_volatile` и `write_volatile` — **не атомарные** операции. Для конкурентного доступа они ведут себя как обычные неатомарные чтения/записи.

## 🔄 `volatile` vs `Atomic`

| Аспект | `volatile` | `Atomic` |
|--------|-----------|----------|
| Для чего | MMIO, сигналы (один поток) | Многопоточная синхронизация |
| Атомарность | ❌ нет | ✅ да |
| Ordering | ❌ нет | ✅ `Relaxed`, `Acquire`, `Release`... |
| Race | UB | Определённое поведение |
| Требует `unsafe` | ✅ да | ❌ нет |

**Правило:** если к памяти обращаются **разные потоки** — используйте `Atomic*`. Если это **MMIO** или **сигнал в одном потоке** — `volatile`.

## 💻 Ваш пример

```rust
use std::ptr::{read_volatile, write_volatile};

fn main() {
    let mut v: u32 = 10;
    let ptr = &mut v as *mut u32;

    unsafe {
        write_volatile(ptr, 40);   // volatile-запись 40
        let res = read_volatile(ptr); // volatile-чтение
        println!("res: {res}");     // res: 40
    }
}
```

### 📝 Что происходит

1. `let mut v: u32 = 10;` — обычная переменная на стеке.
2. `let ptr = &mut v as *mut u32;` — берём адрес `v` и превращаем в сырой указатель.
3. `write_volatile(ptr, 40)` — записываем `40` по адресу `ptr`. Компилятор **обязан** выполнить запись.
4. `read_volatile(ptr)` — читаем значение. Компилятор **обязан** прочитать из памяти, а не подставить `40` из оптимизации.
5. `println!` — выводит `40`.

### ⚠️ Это искусственный пример

С точки зрения результата — код **избыточен**. Без `volatile` было бы то же самое:

```rust
let mut v: u32 = 10;
v = 40;
println!("{}", v);   // тоже 40
```

`volatile` здесь **не нужен**, потому что:
- `v` — обычная переменная, никто извне её не меняет,
- нет MMIO, нет сигналов, нет другого потока.

Пример показывает **синтаксис** и **что volatile-операции работают**, но не демонстрирует **зачем** они нужны на практике.

## 🎯 Где `volatile` действительно нужен

### 1. Memory-mapped I/O (MMIO)

Регистры устройств (UART, GPIO, таймеры) отображены в адресное пространство. Каждое чтение/запись — команда железу.

```rust
const UART_DATA: *mut u8 = 0x1000_0000 as *mut u8;

unsafe {
    // ждём, пока устройство готово
    while read_volatile(UART_DATA) & 0x80 == 0 {}
    // отправляем байт
    write_volatile(UART_DATA, b'A');
}
```

Без `volatile` компилятор мог бы:
- решить, что `0x1000_0000` не меняется, и **оптимизировать цикл** в бесконечный,
- **удалить запись**, потому что результат не используется.

### 2. Разделяемая память между процессами

Один процесс пишет, другой читает. `volatile` гарантирует, что чтение не «закешируется».

### 3. Обработка сигналов

В C/C++ — классический пример: `volatile sig_atomic_t flag`. В Rust — аналогично, но чаще используют `Atomic*`.

### 4. Встраиваемые системы

Микроконтроллеры, где память по адресам — это регистры периферии.

## 📌 Важное замечание про Linux Kernel Rust

В коде ядра Linux `read_volatile` часто используется как временная замена `READ_ONCE()`. Но это **работа вокруг отсутствия API**, а не «правильное» применение. В патчах его заменяют на `atomic_load(Relaxed)`, потому что:

- `volatile` не даёт гарантий против гонок,
- `atomic_load` с `Relaxed` даёт и volatile-гарантии, и атомарность.

## 🆚 `volatile` vs `compiler_fence`

`volatile` влияет **только на конкретную операцию**. Для ordering **между** операциями нужен `compiler_fence` или `atomic::fence`:

```rust
use std::sync::atomic::{compiler_fence, Ordering};

unsafe {
    write_volatile(ptr1, 1);
    compiler_fence(Ordering::Release);   // барьер: всё до — до, всё после — после
    write_volatile(ptr2, 2);
}
```

Без барьера `volatile`-операции **не переупорядочиваются между собой**, но могут «переехать» относительно **обычных** операций.

## 🎯 Итог

| Вопрос | Ответ |
|--------|-------|
| Что такое volatile в Rust? | `read_volatile` / `write_volatile` из `std::ptr` |
| Что гарантируют? | Не удалит, не переупорядочит, не продублирует |
| Чего не гарантируют? | Атомарность, синхронизацию, ordering |
| Где нужны? | MMIO, регистры устройств, embedded, shared memory |
| Где **не** нужны? | Обычные переменные, многопоточность (там `Atomic`) |
| Требуют `unsafe`? | ✅ да |

**Ваш пример** демонстрирует синтаксис, но `volatile` в нём **не нужен** — переменная `v` не является ни MMIO, ни разделяемой памятью. Реальные применения — работа с **железом** (embedded, драйверы) и **разделяемой памятью**. Для многопоточности используйте `Atomic*` — он даёт и volatile-гарантии, и атомарность, и ordering.
